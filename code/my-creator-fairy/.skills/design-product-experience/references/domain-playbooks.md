# Product Introduction Domain Playbooks

## AI SaaS

Prioritize inspectable input and output, human control, reliability boundaries, evidence, and workflow integration. Avoid chat-window mockups when the product's real workflow is not conversational.

Suggested chapters:

`problem -> before/after output -> mechanism -> review/control -> use cases -> evidence -> start`

## Developer Tool

Prioritize stack position, architecture, commands, traces, compatibility, failure behavior, adoption cost, and rollback.

Suggested chapters:

`engineering pain -> alternatives -> product boundary -> request/build path -> failure walkthrough -> quickstart -> closing command`

## Agent Platform

Prioritize the unit of work, plan, permissions, tool use, execution trace, verification, retry, escalation, artifacts, cost, and governance.

Suggested chapters:

`uncontrolled autonomy problem -> agent lifecycle -> permission boundary -> trace -> recovery -> scenarios -> team adoption -> CTA`

The introduction may display a work queue or trace as a screenshot or walkthrough. Do not generate the complete authenticated dashboard unless explicitly requested separately.

## Creator Tool

Prioritize the artifact, creation loop, version comparison, undo, export, and preservation of creative control.

Suggested chapters:

`creative friction -> real artifact -> creation loop -> comparison/versioning -> export -> scenarios -> open workspace`

## General Web Product

Prioritize the literal offer, actual product or inventory, primary workflow, trust conditions, and next action.

Suggested chapters:

`need -> actual product -> how it works -> important terms -> proof -> action`

## Cross-Domain Rule

Choose one primary playbook based on the audience's adoption decision. Do not mix enterprise dashboard density, creator-tool expressiveness, and generic SaaS marketing in the same slide without a deliberate chapter transition.
