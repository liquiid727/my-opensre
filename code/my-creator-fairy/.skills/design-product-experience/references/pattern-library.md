# Product Introduction Pattern Library

## Selection Matrix

| Communication problem | Pattern |
| --- | --- |
| Audience does not yet recognize the problem | Problem Escalation |
| Product belongs to a crowded or unfamiliar category | Landscape Before Differentiation |
| Architecture or workflow is difficult to understand | Progressive Mechanism Reveal |
| Many concepts or capabilities look equivalent | Semantic Accent Grid |
| Product value depends on real scenarios | Scenario-to-Outcome |
| Audience needs a concrete next action | Command-First Closing |

## Problem Escalation

Move from recognizable symptoms to structural cost:

`daily friction -> repeated failure -> organizational consequence -> need for a system`

Use two to four concrete problems. Reveal one at a time. End with the decision the product enables, not with fear.

Avoid generic claims such as "work is inefficient" or unsupported cost estimates.

## Landscape Before Differentiation

Introduce familiar alternatives before explaining the product's position. Compare options using stable dimensions such as control, workflow enforcement, observability, portability, collaboration, and time to value.

Use a table when direct scanning matters. Use a small grid when each option requires a concise explanation.

State where alternatives remain appropriate. Do not create straw-man competitors.

## Progressive Mechanism Reveal

Explain the system with a stable visual skeleton:

1. Input or initiating actor
2. Product boundary
3. Core processing stages
4. Validation or control point
5. Output, feedback, or failure path

Keep existing nodes fixed while revealing new relationships. Provide a complete final state and a static export version.

## Semantic Accent Grid

Use a neutral surface and persistent accent meanings. Limit accent application to borders, headings, icons, and low-opacity backgrounds.

Recommended roles:

- Blue or cyan: system and infrastructure
- Green: success, execution, or primary path
- Purple: intelligence, generation, or orchestration
- Amber: decision, warning, or review
- Red: risk, failure, or anti-pattern

Pair color with labels and icons. Do not assign every card a decorative color.

## Scenario-to-Outcome

Turn abstract capabilities into a compact case sequence:

`starting condition -> product action -> user control -> observable result -> reusable learning`

Use real or explicitly illustrative scenarios. Show artifacts, commands, traces, diffs, or output states rather than claim-only cards.

## Command-First Closing

End a developer-oriented introduction with:

`literal outcome -> minimum runnable command -> primary documentation CTA -> secondary source CTA -> author or trust footer`

Verify the command before publishing. If prerequisites or the command are unknown, mark the closing slide blocked instead of inventing them.

## Recommended Combinations

- AI SaaS: Problem Escalation + Progressive Mechanism Reveal + Scenario-to-Outcome
- Developer Tool: Landscape Before Differentiation + Progressive Mechanism Reveal + Command-First Closing
- Agent Platform: Problem Escalation + Progressive Mechanism Reveal + Scenario-to-Outcome
- Creator Tool: Scenario-to-Outcome + Semantic Accent Grid + artifact-focused closing
- General Web Product: Problem Escalation + Scenario-to-Outcome + action-focused closing
